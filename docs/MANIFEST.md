## P1：陷阱记忆抑制（同模板不同实例）— 2026-10-29

### 动机

基线 smoke 分项中 **G2 = 20**（规则系统应用），最大短板之一。官方 query 中
`Reach 24 using the numbers [5, 5, 5, 8].`（memtrapbench）命中该模式：用户记忆里存着
同一模板的多个历史实例（如 `[6,8,6,8]`、`[8,8,6,7]` 等 20 道 24 点题及其解法），
而 query 问的是一个库中**不存在**的新实例。基线返回 2 条同模板记忆（3829 字符），
Answer 会照抄别的实例的解法 → 按 brief.md 第 33 行（无关/错误记忆污染上下文扣分）被判错。

### 机制

`_apply_trap_suppression(hits, query)`（[main.py](file:///workspace/amc_eval/v5/main.py) 主链路第 9.47 步）：

1. 只对「用给定数字凑目标值」型 query 生效（`_TRAP_PUZZLE_HINT_RE`：`reach/make/form ... using ... numbers` 或中文「用…数字…凑/得/算」），并抽出 query 中的数字列表（`_NUM_LIST_RE`，如 `[5, 5, 5, 8]`，多重集排序去序）；
2. 若候选库中**已存在**该实例（某条 memory 含同一数字多重集）→ 不抑制，属正常召回；
3. 否则判定为陷阱：丢弃所有含数字列表的同模板候选，保留不含数字列表的其它无关记忆；
4. `TRAP_SUPPRESS_KEEP_TOP1=false`（默认）时全丢，返回空列表——宁可弃答也不喂错误解法。

### 开关

| 键 | 默认 | v5 `.env` |
|---|---|---|
| `ENABLE_TRAP_SUPPRESSION` | false（代码默认关） | **true** |
| `TRAP_PUZZLE_MIN_NUMBERS` | 2 | 2 |
| `TRAP_SUPPRESS_KEEP_TOP1` | false | false |

## P2：精排 prompt 可见内容改为滑窗截断 — 2026-10-29

### 动机
官方 smoke 66.26（A 60 / C1 53.33 / I1 29.76）。取证发现精排 prompt 对每条候选
只取 `content[:240]`，而长对话分块的真实答案多在 240 字之后，导致对真阳性打 0 分。

### 机制

## P5：召回/精排候选深度跟随 top_k — 2026-10-29

### 动机
官方 `/search` 固定 `top_k=100`，而召回深度固定 40/50、精排候选固定 40，
答案常落在召回池之外（医疗用户 2024-01-12 处方块完全不在返回的 40 条里）。

### 机制
- `main.py`：`recall_k = max(VECTOR_TOP_K, min(req.top_k, RECALL_DEPTH_MAX))`，
  向量召回首路与 BM25 深度、`[:recall_k]` 截断都用该值；两处 `reranker.rerank`
  调用传 `candidate_limit=recall_k`。
- `reranker.py`：`rerank/_llm_rerank` 新增 `candidate_limit`，实际上限
  `max(RERANK_CANDIDATE_LIMIT, candidate_limit)`，保证不缩回 40。
- `config.py`：新增 `RECALL_DEPTH_MAX`（默认 120，v5 `.env`=120）。

### 配套调参（只为不被排队/抖动误伤，不降低质量）
| 键 | 旧值 | 新值 | 原因 |
|---|---|---|---|
| `RERANK_TIMEOUT_SECONDS` | 20 | 90 | 原超时把信号量排队时间算进去，整批被误判失败→熔断 |
| `RERANK_TOTAL_TIMEOUT_SECONDS` | 120 | 180 | 同上 |
| `LLM_BREAKER_FAIL_THRESHOLD` | 8 | 20 | 避免抖动窗口连锁熔断 |
| `LLM_BREAKER_COOLDOWN_SECONDS` | 60 | 30 | 缩短误熔断恢复时间 |
| `LLM_MAX_CONCURRENCY` | 3 | 9 | 100 候选=9 批，3 并发需 3 波；实测网关 9 并发同时返回约 15s |
